### Bug #16
- Symptoms: `python tests/test_real_screen_capture.py` failed with `Windows screen capture failed: argument 2: OverflowError: int too long to convert`, returning 0x0 dimensions and 0 byte payload.
- Root Cause: Missing explicit ctypes argtypes/restype definition for `gdi32.GetDIBits` on 64-bit Windows systems, causing ctypes to default to 32-bit integer parameters for 64-bit handles/pointers.
- Fix: Explicitly defined Win32 GDI function prototypes in `WindowsScreenCaptureProvider.__init__`: `gdi32.GetDIBits.restype = wintypes.INT` and `gdi32.GetDIBits.argtypes = [wintypes.HDC, wintypes.HBITMAP, wintypes.UINT, wintypes.UINT, wintypes.LPVOID, ctypes.c_void_p, wintypes.UINT]`. Added regression tests in `tests/test_screen_capture_regression.py`.
- Verification: Live screen capture returns 1536x864 dimensions, valid PNG bytes, and real tool output PASS.

### Bug #17
- Symptoms: When the active Gemini credential encountered 429 RESOURCE_EXHAUSTED (free tier limit), the provider retried the exhausted key multiple times with backoff sleep instead of immediately switching to the fallback credential.
- Root Cause: `GeminiLLMProvider.generate` and `GeminiVisionProvider.analyze_image` caught 429 errors and treated them identically to transient network rate limits with exponential sleep retry loops without querying the credential pool for the next healthy key.
- Fix: Enhanced error classification for quota exhaustion terms (`generate_content_free_tier`, `resource_exhausted`, `limit:`, `quota exceeded`); updated `report_failure` to parse dynamic `retryDelay` cooldowns; updated `GeminiLLMProvider.generate` and `GeminiVisionProvider.analyze_image` to immediately failover to the next healthy credential in the 5-key pool on 429 quota exhaustion with 0 retry attempts and 0 backoff delay on the exhausted key; added graceful failure if all credentials in the pool are exhausted. Added comprehensive test suite in `tests/test_credential_failover_chain.py`.
- Verification: Failover chain PASS, immediate switch PASS, 325/325 tests passing.

### Bug #18
- Symptoms: `GeminiVisionProvider` retried the exhausted primary credential multiple times (attempt 1/6 through 6/6) with `ClientError (quota_exceeded)` instead of immediately failing over to the healthy credentials in the pool.
- Root Cause: `GeminiVisionProvider._get_active_api_key()` was resolving credentials without re-querying the pool properly on loop continue, and the loop retry count exceeded the pool credential count.
- Fix: Refactored `GeminiVisionProvider` to directly obtain credentials through `GeminiCredentialPool.get_active_key()`, bound attempts strictly to the pool size, report categorized failures, and immediately skip exhausted credentials with zero sleep delay on 429 quota exhaustion. Added comprehensive unit tests in `tests/test_vision_credential_failover.py`.
- Verification: `python tests/test_real_screen_understanding.py` and `python tests/test_real_voice_vision.py` both PASS using active Fallback 1 credential. 330/330 automated tests pass.

### Bug #19
- Symptoms: `gemini-3.6-flash` Primary hit 429 RESOURCE_EXHAUSTED free-tier quota limit during interactive FRIDAY execution, and FRIDAY continued retrying the exhausted Primary key instead of immediately failing over across the credential pool.
- Root Cause: `GeminiLLMProvider` in interactive mode was receiving an explicit `api_key` string from `Settings` / `factory.py`, causing it to bypass the credential pool's failover logic. Additionally, the generate retry loop bound attempts to `max_retries` rather than the pool length and attempted to reconnect the client on the same key without pool failover.
- Fix:
  1. Updated `GeminiLLMProvider` and `GeminiVisionProvider` to cleanly resolve credentials from `GeminiCredentialPool.get_active_key()`, recreate SDK clients dynamically per key, and bound attempts to pool size.
  2. Implemented immediate 0-sleep failover on `FailureCategory.QUOTA_EXHAUSTED` / `429 RESOURCE_EXHAUSTED` with structured, secret-safe logging (`Gemini credential PRIMARY quota exhausted; switching to FALLBACK 1.`).
  3. Added realistic regression tests in `tests/test_credential_failover_chain.py` covering end-to-end `FridayAgent -> create_llm_provider -> GeminiLLMProvider -> GeminiCredentialPool` failover and cooldown recovery.
- Verification: 331/331 automated unit and integration tests passing (`pytest -q`), zero secrets leaked in logs or `.env`.
