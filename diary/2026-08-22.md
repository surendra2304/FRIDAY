# FRIDAY Engineering Diary — 2026-08-22

## Daily Overview
Today I built an automated cross-provider failover chain for sub-second text reasoning and productized native computer control tools on Windows.

## What I Built Today
1. **Cross-Provider Fallback Chain**:
   - Built FallbackChainLLMProvider enabling instant, automatic failover across free and high-throughput providers: Groq -> Mistral -> OpenRouter.
   - Added model-not-found retries and rate-limit fallbacks so text reasoning never blocks on a single provider outage.
2. **Native Computer Control**:
   - Upgraded application launching using os.startfile and Windows App Paths registry resolution, allowing FRIDAY to launch Chrome, Edge, Notepad, Calculator, and system settings reliably.
   - Built computer control tools: OCR screen reading (pytesseract), smart auto-focus keyboard typing (pywinauto), volume adjustment (pycaw), and power management.
3. **Conversational Fast-Paths & Rich UI**:
   - Added instant greeting fast-paths in process_message so simple hellos return instantly without invoking the full cognitive planning loop.
   - Built a Rich terminal UI with thinking spinners and live status telemetry.

## Problems I Ran Into & How I Fixed Them
- **Browser Launch Failures**: Application().start() failed on Chrome and Edge because they live in Windows App Paths rather than system PATH. I fixed this by using os.startfile with subprocess fallbacks.
- **Groq Model ID Deprecation**: Groq decommissioned older model names resulting in 404 errors. I added internal universal model fallback cascades before escalating to the outer chain.
- **Unused Imports & Dead Code**: Ran a full static analysis sweep and cleaned up 196 dead imports across the codebase.
