## Bugs I Found & Fixed
- **Release Panic Substring Collision**: The phrase "release panic" contained the substring "panic", prematurely triggering the panic activation branch.
  - *Fix*: Re-ordered dispatch branches in `TradingBotOperator.execute()` to evaluate `release panic` before trigger matching.
- **Contested vs Rejected Filter Ambiguity**: The advisory supervisor conflated all rejected advisories with high-confidence contested advisories.
  - *Fix*: Separated `monitor_advisories()` (confidence > 0.70) from generic `get_advisory_recent_rejected` log filtering.
- **Pandas C-Extension Circular Import During Full Suite**: `pytesseract` importing pandas triggered `_pandas_datetime_CAPI` circular import during full test run.
  - *Fix*: Added early safe initialization in `tests/conftest.py`.

## Key Decisions & Architecture
- Enforced immutable command precedence where the trading bot's hardcoded safety gates represent the absolute highest authority.
- Retained the trading bot's own `/api/panic` endpoint as the single authoritative kill-switch mechanism rather than implementing custom kill logic.
- Tagged all AI-Universe recommendations in FRIDAY memory as `TrustLevel.UNTRUSTED_EXTERNAL` to maintain strict cognitive isolation.
- Structured the advisory watchdog as a persistent background operator adhering to OpenJarvis state machine principles.
- Decoupled trading telemetry from general reasoning so AI-Universe communicates directly with the trading engine on a schedule.
- Established consistent telemetry schema parsing across all supervisor queries to support both live and simulated payloads.
