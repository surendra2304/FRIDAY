# FRIDAY Engineering Diary — 2026-08-18

## Daily Overview
Today I laid the initial foundation for FRIDAY on my Windows 11 machine using Python 3.11. I set out to build a lightweight, secure personal assistant that relies on clean native Python abstractions rather than bloated external agent frameworks.

## What I Built Today
1. **Core Intelligence & Engine**:
   - I built the initial framework: custom exception hierarchy, strongly-typed data structures, security configuration, and logging pipelines.
   - I created provider abstractions with unified interfaces, starting with a deterministic `MockLLMProvider`, `OpenAILLMProvider`, and `GeminiLLMProvider`.
2. **Tool Subsystem**:
   - I built an extensible tool registry with automated schema validation.
   - Added core utilities: `calculator`, `get_time_date`, `get_system_info`, `read_file`, and `list_files`.
   - Added a strict 3-tier security classification (`SAFE`, `SENSITIVE`, `DANGEROUS`) requiring explicit confirmation before dangerous actions execute.
3. **ACID Persistent Memory**:
   - I designed a 4-layer memory architecture backed by embedded SQLite with write-ahead logging (WAL).
   - Added FTS5 virtual tables for lightning-fast historical full-text search and integrated Reciprocal Rank Fusion (RRF) for semantic vector search.
4. **Interactive CLI & Voice Prototype**:
   - Built a sleek terminal interface with custom ASCII art.
   - Created the initial Phase 4 turn-based voice prototype.

## Problems I Ran Into & How I Fixed Them
- **Windows Terminal Unicode Crash**: The PowerShell `cp1252` encoding failed on fancy Unicode block characters. I replaced the logo with pure ASCII block art and forced UTF-8 stream re-encoding.
- **Traceback Leaks**: Standard logging filters only checked message strings and leaked credentials during tracebacks. I wrote `SanitizedFormatter` to sanitize all formatted output before writing to disk or console.
- **JSON Serialization Bugs**: Tool arguments were getting converted via `str()` instead of `json.dumps()`. I updated message serialization to ensure standard JSON compliance.
- **Path Traversal Risk**: File reading tools could have escaped the working directory. I locked down `read_file` and `list_files` to strictly reject unauthorized paths.

## Testing & Verification
- I wrote and ran 168 automated unit tests covering engine loops, tool registry boundaries, SQLite transaction safety, and RRF hybrid search.
- All 168 tests passed in 31.03s with sub-2ms database lookups.
